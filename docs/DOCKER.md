# Docker & Deployment

## 1. Files

| File | Purpose |
|------|---------|
| `backend-laravel/Dockerfile` | Production app image (nginx + php-fpm via `richarvey/nginx-php-fpm:3.1.6`) |
| `backend-laravel/docker-compose.yml` | Local full-stack: app + PostgreSQL 15 |
| `backend-laravel/render.yaml` | Render blueprint (web service + managed Postgres) |
| `backend-laravel/.env.example` | Env template (PostgreSQL profile) |

## 2. Dockerfile (`backend-laravel/Dockerfile`)

```
FROM richarvey/nginx-php-fpm:3.1.6
WORKDIR /var/www/html
COPY . .
RUN composer install --no-dev --optimize-autoloader --prefer-dist --no-interaction
RUN if [ -f package.json ]; then npm ci && npm run build; fi   # builds SPA if present
RUN chmod -R 775 storage bootstrap/cache \
 && chown -R www-data:www-data storage bootstrap/cache
ENV WEBROOT=/var/www/html/public
EXPOSE 80
```

Notes:

- The base image handles nginx + php-fpm + a supervisor process.
- `WEBROOT` points Laravel's document root to `public/`.
- Build args/env are injected at runtime (Render env vars / compose).
- The image expects environment variables (APP_ENV, APP_KEY, DB_*, etc.); `COPY . .` includes `.env` **only** if present — avoid committing `.env`; prefer env vars.

## 3. docker-compose.yml

```
services:
  app:
    build: .
    ports: ["8080:80"]
    environment:
      APP_ENV: local
      APP_DEBUG: "true"
      DB_CONNECTION: pgsql
      DB_HOST: db
      DB_PORT: 5432
      DB_DATABASE: laravel
      DB_USERNAME: laravel
      DB_PASSWORD: secret
    volumes:
      - ./:/var/www/html
    depends_on: [db]
  db:
    image: postgres:15
    environment:
      POSTGRES_DB: laravel
      POSTGRES_USER: laravel
      POSTGRES_PASSWORD: secret
    ports: ["5432:5432"]
    volumes: ["dbdata:/var/lib/postgresql/data"]
volumes:
  dbdata:
```

Usage: `cd backend-laravel && docker compose up --build` → app at `http://localhost:8080`, DB at `localhost:5432`.

> Note: compose mounts the repo over `/var/www/html`, so local source changes apply immediately; DB creds are compose-specific (`laravel/secret`), different from `.env.example` (`postgres/…`). Use `php artisan key:generate` + `php artisan migrate --seed` after first up (auto-run scripts are not wired).

## 4. render.yaml (Render blueprint)

```yaml
services:
  - type: web
    name: studentnest-web
    env: docker
    repo: https://github.com/Muhamedall/studentnest-fullstack-projct
    branch: main
    plan: starter
    dockerfilePath: Dockerfile
    envVars:
      - key: APP_ENV        value: production
      - key: APP_DEBUG      value: "false"
      - key: APP_KEY        generateValue: true
      - key: DB_CONNECTION  value: pgsql
      - key: DB_HOST / DB_DATABASE / DB_USERNAME / DB_PASSWORD  (fromDatabase: studentnest-db)
databases:
  - name: studentnest-db
    type: postgres
    plan: starter
```

Notes:

- The **worker service was removed** (Phase 7) — the app dispatches no queued jobs, so a worker was dead weight.
- `APP_KEY` is auto-generated by Render; DB config comes from the managed database.
- For payments, add `FRONTEND_URL`, `STRIPE_KEY`, `STRIPE_SECRET`, `STRIPE_WEBHOOK_SECRET`, and for images a storage bucket (currently local `/public` disk).

## 5. Local (no Docker) vs Dockerized

| Concern | No Docker (php artisan serve) | Docker compose |
|---------|-------------------------------|----------------|
| DB | SQLite (file) | PostgreSQL 15 (container DB `laravel`) |
| Web | `artisan serve` :8000 | nginx+php-fpm :8080→80 |
| Frontend | Vite dev server :3000 | optional `npm run build` → served by Laravel? No — SPA served separately during dev |
| Storage link | `php artisan storage:link` needed | handled at build/start depending on setup |

## 6. Gotchas

- `richarvey/nginx-php-fpm` expects the app under `/var/www/html` and requires writable `storage`/`bootstrap/cache`.
- If you `COPY . .` with a `.env` present, secrets could leak into the image — prefer Render/Compose env vars.
- Migrations **are not** automatic at container boot. Run `php artisan migrate --seed` after starting (one-off `docker compose exec app php artisan migrate --seed`).
- The frontend is **not** bundled inside the Laravel image in this repo layout (SPA runs via Vite in dev; in real prod you'd build and copy `frontend-react/dist/` into `public/` or serve it via a CDN/static host).
